## 2. DUPLICATE CODE PATTERNS

### High-Priority Consolidation Opportunities:

**A. Similar box styles in Techstack.js vs Toolstack.js**

- **Techstack.js** (lines 8-21): `boxStyle` object with gradient background, borderRadius, boxShadow, border, display flex, flexDirection, alignItems, justifyContent, height
- **Toolstack.js** (lines 7-20): `toolBoxStyle` object with backgroundColor, borderRadius, boxShadow, transition, border, display flex, flexDirection, alignItems, justifyContent, height, cursor

**Recommendation**: Extract a shared style constant or CSS module. Both styles serve the same purpose (card-like boxes for tech/tool items) and differ only in subtle details (gradient vs solid bg, shadow color).

**B. Hover effect patterns in Techstack.js vs Toolstack.js**

- **Techstack.js** (lines 23-44): `hoverEffect` object with onMouseEnter/onMouseLeave that uses `e.currentTarget.querySelectorAll('svg')` and `e.currentTarget.querySelectorAll('div')` to change colors
- **Toolstack.js** (lines 22-30): Separate `onMouseEnter` and `onMouseLeave` functions with simpler style transitions

**Recommendation**: Unify the hover interaction pattern. The Techstack version is more complex (querySelector for icons/text), while Toolstack is simpler. Could create a shared hover utility component.

**C. Inline keyframe animations duplicated across About.js and Home2.js**

- **About.js** (lines 323-400): `<style>` block with keyframes: fadeInUp, fadeInRight, fadeIn, expandWidth, gradientShift, gradientSlide, float, pulse
- **Home2.js** (lines 169-207): `<style>` block with keyframes: float, fadeInUp, fadeInRight, scrollbar styles

**About.js keyframes**: fadeInUp, fadeInRight, fadeIn, expandWidth, gradientShift, gradientSlide, float, pulse
**Home2.js keyframes**: float, fadeInUp, fadeInRight (plus scrollbar)

**Recommendation**: Extract shared keyframes (fadeInUp, fadeInRight, float) to a global CSS file. The About.js-specific animations (gradientShift, gradientSlide, pulse, expandWidth) and Home2.js-specific scrollbar styles can remain component-specific.

**D. Github component referenced but removed in About.js**

- **About.js** (line 235): `// Removed: { title: "Days I", highlight: "Code", component: <Github /> }`
- **Github.js** (src/components/About/Github.js): Component exists but is entirely commented out with `{/* ... commented content ... */}` and a note: "This component is kept for 'name's sake' as requested, but it currently does not display any content."

**Recommendation**:
1. Remove the commented-out reference in About.js (line 235)
2. Either delete Github.js entirely or restore it with actual content if still needed

**E. Overlapping skill/tools content between Techstack.js and Toolstack.js**

- **Techstack.js** lists under "Core Competencies": UX Research, UI/UX Design, Tech & Web, Tools (Figma, Canva, Photoshop, Microsoft 365 Copilot), Collaboration (Notion, Slack, Google Workspace)
- **Toolstack.js** lists: Figma, Notion, Slack, Canva, Google Workspace, Adobe Photoshop

**Recommendation**: The "Software & Tools" section in Techstack.js (lines 101-136) and Toolstack.js have significant overlap. Consider:
- Consolidating into a single component
- Or having Techstack focus on UX/UI competencies and Toolstack on actual tools used, with no duplication
